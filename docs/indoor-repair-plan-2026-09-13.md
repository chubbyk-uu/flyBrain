## 2. 冻结项及新的场景约定

- 保留 CUDA MaleCNS v1.0 brain + VNC pack、现有神经元身份和数组哈希；神经0.1 ms、物理
  MuJoCo 0.2 ms、控制窗口2 ms；保留完整身体，暂不简化关节或气动力。
- 环境从空房间定义新建，建议版本名 `indoor-v2`；不以加载旧房间后隐藏/搬动家具实现。
  可以复用身体资源、加载器、Three.js renderer、桥接协议和代码，旧环境仅作为独立历史选项。
- 新建小室内房间，无地垫；一张低矮、长条茶几，花盆及带香味糖果都在茶几上。
  茶几候选长宽高180×80×30 mm；尺寸在阶段1确认并冻结，必须兼顾20秒近源任务可达性。
- 房间、家具、盆栽、糖果的材质和贴图重新配置，不沿用旧环境的装饰、木纹或地垫拼装。
  贴图可用新制程序纹理或许可明确的新资产；视觉形状和碰撞近似的差异须标注。
- 新版场景、物理、资源坐标使用同一权威定义；禁止启动时暗中将糖源移到果蝇前方。
- 首版无环境风：气味场和动力学环境气流均为 `[0,0,0]`；保留自身运动造成的相对气流和
  飞行空气动力。旧大场景 `[35,8,0]`、旧小场景 `[12,-3,0]` mm/s 仅作为历史配置。
- 两个食物资源 ID 独立，共用一种吸引性食物气味和受体编码；先采用相同释放强度及衰减参数，
  使用静态三维距离衰减，局部浓度为两源贡献之和。初版不加入不同气味身份或偏好选择器。
- 无风同强度时，单源贡献随三维距离减小而增加；混合梯度不保证指向最近源。控制依据局部
  感觉和进展，不用真实资源坐标选最近食物；真实坐标仅用于环境生成、出生布局及离线评分。
- 默认允许近源出生，以便尽快看到寻食：在一个源附近的合法支撑面出生，姿态稳定、无穿模、
  尚未接触食物。建议口器距源中心15–35 mm，至少超出味觉接触边界5 mm；不强制正对食物。
  固定默认布局和测试出生点后不得按失败结果偷偷挪近。近源成功不宣称全房间任意出生成功。

## 3. 首次网页连接和重置的最终约定

本节采用用户最后一次更正，取代“后台等待网页才开始”和“首次网页还需点击开始”的旧方案。

- 后台完成加载后即开始仿真。
- 当前后台进程第一次收到正式 viewer 的“场景/显示已就绪”通知时，自动完整重置一次，然后
  继续运行，让第一次打开网页从初始状态观看。原始 WebSocket 连接、诊断客户端或图库连接
  不应提前消耗这一次重置。
- 一次性标记由后台持有，不能只依靠标签页变量/localStorage；同一后台下刷新、重连、新
  标签页、多客户端同时连接，均不重复自动重置。重启后台才开启新一轮一次性资格。
- 网页提供暂停、继续、手动重置、全景视角。手动重置恢复初始状态并暂停，等待继续；手动
  重置不重新开放“首次网页”资格。
- reset 覆盖 CNS、身体、时间、饥饿、疲劳、清洁冲动、行为控制器/随机状态及感觉缓存。
  发布新的 epoch；浏览器清除旧 pose 插值、retina 和翼动画状态，不混播前后两段状态。

## 4. 需求状态、视觉和神经参与边界

- 页面显示饥饿度、疲劳度、清洁冲动，以及行为、暂停状态、起飞受限/恢复搜索原因。
  饥饿和疲劳用0–100%；清洁冲动可显示低/中/高及数值，不再使用积灰度/清洁度作为产品名称。
- 清洁冲动是单一 `[0,1]` 工程倾向值：随时间累积，在安全、不饿、稳定支撑及神经门控满足时，
  以固定种子可复现的机会触发一套搓腿—擦头/眼流程；完成后下降，有滞回及冷却。
  不模拟真实灰尘，也不声称已恢复清洁动机的生物机制。旧 dirt 字段的兼容迁移须显式记录。
- 地板和茶几顶面均允许清洁，不能用绝对 `z <= 5 mm` 把桌面支撑排除；飞行、危险及紧急
  寻食可推迟/中断。不能因跳入清洁状态就给予完整动作完成奖励。
- 现状参数供回归参考：初始 hunger=0.72，未进食每秒+0.001，有效进食每秒−0.22；饥饿
  开/关阈值0.55/0.30。fatigue 初值0.05，有功飞行每秒+0.02×努力系数，至少三足地面
  支撑时每秒−0.06；0.68请求落地，≤0.25且累计10秒支撑才解除疲劳起飞禁令，前3.5秒休息。
  当前遗漏低水平速度悬停；新版须修正。爬行恢复符合用户最新要求，应保留；不再将其列为缺陷。
  参数变化须记录，不能假装已实现。
- 新版fatigue明确为“飞行疲劳”：飞行及有功悬停均累积，不以水平速度>1 mm/s作为必要条件；
  地板或茶几等表面稳定支撑后，爬行与静止都恢复。正常飞行目标约30–45秒达到降落门槛，
  落地恢复起飞资格目标约10秒，期间允许爬行，不强制3.5秒静止。实际时长随起始疲劳和
  努力系数变化；验收须登记标准起点/功率，并分别记录达到疲劳阈值和真正降落的时间。
- 清洁机会的新节奏：从默认低冲动开始约10–15秒达到可触发水平；完成后约10–20秒再次
  出现机会，间隔按仿真时间及固定种子随机变化。完整合并动作2–3秒，冷却至少5秒，包含在
  完成到下一机会的间隔内，不额外叠加。首次时间从正式初态计，后续从上次动作完成计。
  饥饿、飞行或不安全时只推迟执行，恢复后择机执行；不累计待办次数，不连续补做清洁。
- 当前正常吃饱在hunger约0.30时退出进食，按每秒+0.001，到0.55重新饥饿约需250仿真秒
  （约4分10秒，离散步进可有微小差异）；当前饥饿增长不区分飞行、爬行或休息。
  用户已确认新版改为吃饱后约60仿真秒重新饥饿：保留0.30/0.55阈值时，未进食增长率
  应为 `(0.55-0.30)/60 = 0.0041666667/s`。该修改待实施，现运行代码仍为250秒周期。
  新增固定状态fixture：从0.30、无进食开始，60秒±一个控制窗进入饥饿；实际餐后记录
  阈值越界的小量误差。不能为通过验收加快仿真时钟、强制饱食进食或中途重置需求状态。
- 初始20秒寻食用饥饿、低疲劳、低清洁冲动，不额外叠加10秒出生休息。出生应站立显示，
  不强制立即起飞，也不要求有用的神经起飞驱动必须被无限抑制。
- native 双眼图像继续提供预览。当前 MaleCNS 使用速度/几何距离计算的 motion/loom 代理，
  不是由双眼像素提取，也未实现糖果/花识别或双目高度定位。
- 上游 pack 对未支持递质省略出边，其中包括组胺感光通路；用户已明确暂缓此问题。
  本轮不改 pack、不恢复组胺通路、不迁移 browser retina、不把两种气味身份识别列为完成项。
- 工程规则可决定搜索策略和解除起飞禁令；实际运动及进食须有 CNS 输出的因果参与。

## 5. 分阶段实施与硬门控

### 阶段1：全新环境及实际视觉审查

建立独立环境、全新材质、矮长茶几及桌上糖果/开花盆栽；同步全景和特写相机。

- 新环境不引入 legacy 家具/装饰；所有环境几何位于房间边界内（边界墙体自身厚度除外），
  无房外残留、地垫、悬浮家具、脱节桌腿、断开的植物或明显穿插。
- 保存全景、四方向、茶几、花盆、糖果近景并逐张查看；不能以图片非空或加载成功代替美术验收。
- 身体质量、惯量、关节、执行器契约保持；新环境不增加动态 DOF；地板、茶几和花蜜支撑处
  各稳定5仿真秒，末2秒垂直速度绝对值中位数≤2 mm/s，无持续穿透增长和物理 warning。
- 静态源中心与权威 geom/site 定义误差≤0.5 mm；默认近源出生满足第2节条件。

### 阶段2：气味、接触和场景一致性

取消启动移动糖源；实现无风同气味双源，核对显示、物理、味觉区域。

- 同强度单源在固定三维采样点满足距离衰减；双源场等于两份贡献之和；关闭任一源后不残留
  该源贡献，另一源仍正常；输入编码有限、有界，不因叠加直接饱和至无法辨别测试梯度。
- 单独验证糖果和花蜜接触内外：进入/离开区域20 ms内更新对应 taste ID；盆底、空中或
  仅靠近装饰糖果不能误算进食。双眼图像左右正确、对象位置一致；这里只验收可见性。
- 初始食物位置、重置后位置与场景一致；记录源参数、位置、出生点及资源哈希。

### 阶段3：首次网页重置及状态界面

按第3节实现启动协议与网页控制，显示第4节状态。

- 后台独立运行5秒，时间确实推进；首次正式网页 ready 后产生且仅产生一次 reset epoch，
  显示初始状态后连续运行；不将加载时间计入正式起点。
- 刷新、断线重连、新标签页、两个页面同时 ready 和诊断客户端连接均不得造成额外自动重置；
  重启后台后重新允许首次网页自动重置。
- 暂停5墙钟秒，神经、物理时间及内在状态均不推进；手动重置后初值正确且保持暂停。
- reset 后没有旧 pose/retina/状态混入；界面状态来自 native snapshot，不能用网页另算一套值。

### 阶段4：飞行速度、起降和翼展开

统一常规、近食物、避障路径的速度/加速度限制，区分翼展开基姿与周期振翅。

- 常规水平速度指令60–100 mm/s，近目标15–40 mm/s；所有正常/避障分支均遵守100 mm/s
  指令上限。实际稳态水平速度p95≤120 mm/s，非碰撞峰值≤150 mm/s；碰撞峰值另报，不可隐去。
- 对每个控制窗的指令加速度设统一有限上限；值在阶段实现前登记，禁止以跳变达到速度目标。
- 地板、茶几各5次起降无弹射、穿透、翻倒或自动 reset；记录起飞状态时长、实际升降速度、
  触地速度及支撑转移。55 mm高度着陆fixture在3.5秒内稳定支撑；低空食物fixture保留原门控。
- 飞行俯视最大展开角按身体纵轴衡量，每侧90°±10°；不得拿局部关节摆幅代替该指标。
  保存俯视/侧视慢速审查视频；无穿体、脱胸、长串重影，地面收翼，左右调制仍响应神经/控制信号。

### 阶段5：20秒近源寻食及绕盆脱困

记录局部感觉变化、重复访问及真实进展；取消“闻到目标便永远禁止地面起飞”的仲裁。
持续受阻时允许退开、换方向、垂直采样及 CNS 门控的起飞；不访问食物坐标导航。

- 四类固定任务：地板→茶几糖果、茶几→高处花蜜、盆底→花蜜、双源→任一食物。
  各5个预先固定种子（11、13、17、19、23）及登记的出生点/朝向；单源条件须独立关闭另一
  食物的吸引输入。默认演示可近源出生；跨高度任务若不符合15–35 mm建议，必须事先登记。
- 每类至少4/5在20仿真秒内开始有效进食；有效进食需接触、支撑、MN9活动、口器伸展及
  hunger下降同时成立，并持续至少0.2秒，不能只以 FEED 标签或一次taste脉冲判成功。
- 时间从正式初始状态计起，后台预运行不算；统计全部失败、首次进食延迟、源ID及出生距离，
  不只挑成功种子。20秒内进食不要求20秒内吃饱。
- 有搜索意图、可活动时连续3秒无进展应触发恢复；随后5秒内离开原局部循环或取得新进展。
  正常进食、明确疲劳休息和有效清洁不作为搜索卡死，但不能靠切状态逃避检测。
- 进展检测同时看空间重复、位移、感觉历史，路径长度增加本身不算进展。检测器阈值先在
  合成绕圈、往返、正常休息和真实接近fixture中冻结，再读取验收轨迹。
- 配对运动输出断连不应保持同等主动寻食；嗅觉诱发输入断连应改变定向表现。保留原始
  脉冲/命令/轨迹证据，不能以全脑仍在计算证明神经有作用。

### 阶段6：清洁冲动、饥饿及疲劳闭环

- 归一化状态有界、暂停冻结、reset回初值、固定种子可复现；仅实际进食降低饥饿。
- 飞行疲劳fixture分别覆盖正常飞行、水平速度为0的有功悬停、低速悬停，三者均单调增加；
  稳定支撑的爬行与静止分别单调恢复。无支撑下坠不能冒充落地恢复，暂停不得累计或恢复。
  标准恢复起点和飞行功率fixture应在30–45秒达到降落阈值；标准落地疲劳fixture在约10秒
  （验收9–11秒）恢复起飞资格，爬行与静止均通过。真实飞行记录初始疲劳以解释时间差异。
  恢复资格不强制立即起飞；有正常神经驱动时不得被食物气味永久禁止起飞。
- 取消旧“低冲动30秒始终不触发”门槛：自然累积本应在10–15秒内产生首次机会；只有固定
  在阈值以下的受控fixture才要求不触发。测试机会产生时间与实际动作启动时间，二者不能混用。
  饱食、安全、神经门控持续有效的fixture中，机会出现后2秒内应启动；高冲动初态亦覆盖。
- 地板及茶几均覆盖；完整动作2–3秒，先搓前足再擦头/眼，完成后冲动下降且冷却至少5秒。
  连续20个可执行机会的间隔均在10–20秒范围内且非全部相同；同种子重放相同，不同种子
  不固定相同间隔。长时间飞行/饥饿后恢复仅保留一次机会，不出现补做连发。
- 保留至少四足支撑，前足互距和前足到头/眼距离分别出现<1.5 mm的对应阶段；动作结束
  可恢复爬行。饥饿/危险中断不记完整完成，门控/运动输出断连不能完成同等清洁。

### 阶段7：最终网页及长程整体验收

- 最终相同版本、配置和场景：上述5个种子各300仿真秒（用户更正，替代600秒），逐条包含
  飞行、稳定休息、爬行，并在同一次运行中分别实际取食糖果和花蜜至少一次；只有反复取食
  同一个源不能通过，也不能用不同种子各取一个源来拼成双源成功。
  两源都沿用阶段5的有效进食判据，记录每餐时间、资源ID、饥饿前后值和源间转移。
  不要求固定取食顺序，不用定时强制换目标或真实源坐标导航来满足多样性；失败应定位搜索、
  餐后离开、局部记忆或饥饿周期的原因，再改实现。
- 至少4/5出现自主合并清洁；全部通过无进展恢复门控，无长期盆底绕圈或重复穿房循环。
- “不机械重复”与“不无所作为”同时验收：不仅统计动作次数，还报告每类行为的总时长、
  bout次数/间隔、最长连续时长、空间覆盖、资源转移、最长无有效进展时间及其原因。
  清洁动作内部重复搓擦、合理餐次和疲劳周期本身允许；不允许高层行为固定按同一时间表
  播放，或长时间重复同一路径却没有感觉/需求上的进展。
- 在无进食、无有效清洁、无疲劳恢复需要、无持续安全限制且运动神经输出有效时，连续
  10秒停在同一5 mm邻域、没有新搜索进展即判异常，须回溯3秒检测和随后5秒恢复门控；
  局部绕圈即使累计路程很长也不能算活跃。正常停留只有同时存在对应物理/状态变化才豁免，
  单改behavior标签不能豁免，持续安全限制也必须单列原因和时长、检查可否脱困。
- 对每个种子增加同初态的局部感觉扰动对照（例如在已登记时刻关闭正在追踪源的气味），
  检查搜索响应是否随输入改变；继续完全相同的动作/轨迹循环须调查，不能以随机间隔掩盖
  感觉无效。单次0.2秒接触、瞬间起飞或静止标签不能单独证明完整行为：视频与物理事件交叉核对。
- 每条检查异常片段视频及轨迹，保存正常进食、起降和清洁视频；不能用手动触发充当自主事件。
- Windows Chrome/RTX 5080正式viewer连续10墙钟分钟，前台60 FPS目标，平均≥55 FPS、
  帧间隔p95≤25 ms；25–30 Hz新鲜pose、10–15 Hz双眼预览，阴影开启，无重影或队列持续增长。
